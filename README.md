# Jev 課程人才圖像 Demo

展示網址：https://clchrf.github.io/jev-course-demo/

輸入一門課的名稱與完整課綱，一次檢視大專院校（IV）ABCD 四大能力與 11 項核心細項。版面沿用《Jev AI.pdf》的卡片、課程涵蓋開關與四項檢視。

- **分數**：依「證據尺規」比對課綱原文，規則公開，可追溯到官方 IV 定義與課綱原句。
- **模型**：真實的 Laya multilingual（量化 ONNX）在瀏覽器內推論，**沒有串接 Jev 官方 API**。模型機率另列，不計入分數，也不觸發複核（原因見〈診斷〉與〈Laya 的角色〉）。
- 沒有預填分數，沒有辨識範例文字的規則，也沒有隱藏加分（`tests/` 內有檢查）。

## 現場示範

1. 用電腦版 Chrome 或 Edge 開啟網頁。
2. 按「載入完整課程範例」，或貼入自己的課綱。
3. 按「開始檢視 ABCD」。尺規結果會立即出現；接著 Laya 在背景逐段運算（首次下載約 305 MB 模型，之後使用瀏覽器快取）。
4. 在上方 A–D 總覽跳到各能力。每個細項會顯示證據等級（L0–L4）、四種證據是否出現、Laya 機率，以及需人工複核的原因。
5. 展開「尺規依據、模型提問與對照原文」，以及右側「Laya 呼叫紀錄」，可以看到每段原文的尺規比對與模型原始回傳。
6. 載入空泛反例，再執行一次比較。修改文字或涵蓋開關後，舊結果會立即清除，不會把舊分數當成新結果。
7. 「下載檢視結果」會輸出 JSON，內容包含課綱、分段、每段尺規比對、模型原始回傳、問題設定與彙整結果。

## 評分規則（v2 證據尺規）

### 1. 分段

課綱依空白行、週次開頭（「第 3 週」「Week 3」）與條列項目切成教學段落。課程名稱只用來判斷課程是否有 AI 情境，不算證據。超過模型容量的段落會再依 tokenizer 切開，確保尾段不被截掉。

### 2. 每個細項的證據（`assets/rubric.js`）

每個細項都有：

- `trace`：對應的官方 IV 定義原句。
- `anchors`：定義中可觀察的具體行為，例如 B-2 的「查核、查證、偏誤、誤判、AI 產出的錯誤」，D-2 的「訪談、角色扮演、與使用者溝通」。只有 anchors 能構成練習證據。
- `mentions`：能力名稱層級的字詞，例如 D-3 的「創造力、創新」。只會得到 L1。
- 依細項說明什麼算練習、產出、檢核（頁面上可展開查看）。各細項的證據並不相同。

通用的教學線索有四類：學生活動（週次、實作、分組、訪談…）、具體產出（繳交、紀錄、報告…）、驗證／反思／評量（評分、尺規、配分 %、比對、反思、誤判率…）、具體數量。另有三項處理：

- **目標句**（「培養…能力」「透過專題提升…」，且沒有數量或產出）只算提及。
- **否定子句**（「不安排…」「未要求…」）中的線索全部忽略。
- **AI 情境**：整門課沒有任何 AI 字詞時，所有細項都是 L0。A/B/C 的練習段落若本身沒提到 AI，會標示需人工複核。

### 3. 證據等級

| 等級 | 名稱 | 條件 | 換算 |
|---|---|---|---|
| L0 | 未見 | 沒有相關敘述 | 0 |
| L1 | 僅提及 | 只有能力名稱、目標句或被否定的活動 | 25 |
| L2 | 有練習 | 同段落有此細項的具體敘述，且有學生活動 | 50 |
| L3 | 有產出或檢核 | L2，加上具體產出，或驗證／反思／評量其一 | 75 |
| L4 | 產出且檢核 | L2，加上具體產出與驗證／反思／評量 | 100 |

### 4. 整門課彙整

同一細項的證據在所有段落間以 OR 合併：活動寫在第 4 週、配分寫在最後的評量表，也會合併。內容相同的段落只算一次，段落順序不影響結果。因此不再「只取 alignment 最高的單一段落」，也不再「取各段最高機率」。

### 5. 分數與四項指標

- **向度分數**＝該向度細項等級的平均 ÷ 4 × 100。75 以上「很好」（平均達 L3），50–74「尚可」（平均達 L2），未滿 50「要補強」。
- 四項指標只作診斷，**不再等權平均成總分**：
  - 對到定義 `alignment`：有練習（≥L2）的細項比例。
  - 看得到做法 `concreteness`：有練習的細項中，產出、檢核、具體數量三者的平均。
  - 成果不誇大 `supported`：練習段落 ÷（練習段落＋只寫目標的宣稱句）。
  - 不是範本 `boilerplate`：相關敘述中非空泛目標句的比例。
  - 沒有相關敘述時顯示「—」，不給分數。
- **狀態**：「證據不足」＝沒有任何細項達 L2；「需人工複核」＝A/B/C 某細項的練習段落本身沒有提到 AI（AI 情境來自課程其他段落）。
- 這是展示用尺規，**不是教育部官方量尺**，也**不等同**《AI人才圖像核心能力初評工具》的 0–5 課程培養程度評分，兩者不可混用或換算。

### 6. Laya 的角色

每一段 × 每個細項送一個 `noul` 問題（`RUBRIC[id].model`，附 true/false 描述），取得 P(是)。段落過長時取該段各部分的最高值。頁面顯示：

- 練習段落的 P(是)，以及全課程最高的 P(是) 與所在段落。
- 是否與尺規方向一致：尺規 ≥L2 時看練習段落 P ≥ 0.5，尺規 <L2 時看全課程最高 P < 0.5。
- 該細項在校準集上的 AUROC（`MODEL_CALIBRATION`），AUROC < 0.7 或無正例時註明不可靠。

模型機率**不改變等級、分數或複核狀態**。原本設計了兩種由模型觸發的「需人工複核」旗標（尺規有練習但 P < 0.5；尺規沒有但 P ≥ 0.9），在校準集上它們在 121 格中觸發 51 格，卻沒有抓到任何一格規則與暫定標籤不一致的情況，因此不採用。

## 診斷：v1 為什麼不可靠

腳本在 `calibration/`，結果在 `calibration/results/`。使用與頁面相同的 bundle 與量化權重，透過 onnxruntime-node 1.30 重現。

**重現 v1**（`repro-legacy.mjs` → `legacy-repro.json`）：完整範例 A60 B57 C60 D42，空泛反例 A48 B40 C56 D39，與先前頁面實測一致。反例的 alignment（62–66）反而高於正例（59–60）；D 取到的是第 3 段評論分析專題。

**模型執行本身沒有錯**（`diagnose.mjs` → `diagnose.json`）：

- tokenizer 與 Hugging Face `tokenizers` 對正、反例及問題文字的編碼完全一致。唯一差異：罕見字與 emoji 在 bundle 中變成 `<unk>`，官方實作則使用 byte fallback，對一般中文課綱沒有影響。
- 問題 prefix 最長 75 tokens，沒有任何問題被 `head_max_len` 截斷。頁面的段落預算 760 tokens，加上 prefix 仍小於 1024，課綱不會被截斷。
- 同一問題單獨送出與 3 題一批送出，結果完全相同（最大差 0），批次處理正確。
- 輸出解析與 Laya 官方 Python 版一致：`noul` 取 softmax 第 2 格，`score` 取期望值。溫度皆為 1.0。

**問題出在把模型當成評分器**：

- `score` 題有位置偏誤（Laya README #131：multilingual 幾乎不選第 0 級）。無關文字、天氣句、化學實驗的 alignment 仍有 1.5–2.1（×25 ≈ 38–52 分），所以 v1 的正反例都落在 40–60。
- `noul` 能辨識「有沒有 AI 相關活動」與否定句，無關文字與否定句接近 0。但它分不清是哪個細項：11 題對 11 段針對性短文的矩陣中，對角線與非對角線同樣接近 1.0（`probe-matrix.mjs`）。它也分不清「只寫目標」與「實際練習」（`probe-tiers.mjs`）：目標句 0.96、只列工具名稱 0.99、實際練習 0.99。
- 用 11 選 1 的 `choice` 題判斷細項接近隨機（`probe-choice.mjs`）。encoder 向量與官方定義的相似度也無法區分細項（`probe-embed.mjs`）。
- Laya README 也寫明：base checkpoint 在零樣本決策上接近隨機，需要針對領域微調。

因此 v2 不讓模型機率決定分數，改由可檢查的尺規給分。模型機率仍會實際推論並完整列出，只作為對照參考。

## 校準與驗證

- `calibration/cases/calibration.mjs`：11 門課（內建正反例、部分涵蓋、無 AI、只列工具、否定句、重複文字、長課綱尾段、其他領域、只有 A 的證據、活動與評量分開寫）。用來發展規則，並評估由模型觸發複核旗標是否有用（結論：沒有用）。
- `calibration/cases/validation.mjs`：12 門課，**規則凍結（commit c32da85）後才撰寫**，換了科系與寫法（另加教師示範、只有目標與配分、中英混寫），未用來調整規則。
- 每個案例都標示預期等級與理由。**這些是 Claude 擬定的暫定標籤，不是教師或專家人工標註**，需由人複核。
- `node calibration/run.mjs calibration`、`node calibration/run.mjs validation`：輸出 v2 等級、Laya 原始回傳、v1 分數與變形測試（段落重排、整份重複、刪除關鍵段落），存成 `results/<set>.json`。
- `node calibration/report.mjs` 產生 [`calibration/results/REPORT.md`](calibration/results/REPORT.md)，內含修改前後逐案比較。

### 結果摘要

完整逐案表格見 [`calibration/results/REPORT.md`](calibration/results/REPORT.md)。以下「一致率」都是與**暫定標籤**比較。

| | 校準集（11 門、121 格） | 驗證集（12 門、132 格，規則凍結後撰寫） |
|---|---|---|
| v1：細項 P(是) ≥ 0.5 判為涵蓋的一致率 | 40.5%（AUROC 0.64；93 個未涵蓋格誤判 68 個） | 40.2%（AUROC 0.62；116 個未涵蓋格誤判 79 個） |
| v2：≥L2 判為涵蓋的一致率 | 97.5% | 95.5% |
| v2：證據等級完全一致／差 ≤1 級 | 94.2%／96.7% | 91.7%／95.5% |
| v2：把其他證據誤算成此細項 | 2 格（A-2，同一段在重複案例中出現兩次） | 0 格 |
| v2：漏判（應 ≥L2） | 1 格 | 4 格（英文 2、B-2 特殊寫法 2） |
| 段落重排／整份重複／刪除關鍵段落 | 不變／不加分／降至 <L2 | 不變／不加分／降至 <L2 |

**修改前後的重點比較（A/B/C/D）：**

| 檢查 | 案例 | v1 | v2 |
|---|---|---|---|
| 具體活動是否優於空泛宣稱 | 內建完整範例 vs 空泛反例 | 60/57/60/42 vs 48/40/56/39 | 100/67/67/50 vs 25/25/17/17 |
| | 驗證：機械設計 vs 智慧觀光空泛課綱 | 71/70/72/68 vs 61/57/62/58 | 25/25/17/33 vs 13/8/8/17 |
| 無關課程是否不會輕易高分 | 中級會計（無 AI） | 48/48/48/52 | 0/0/0/0 |
| | 驗證：台灣史（無 AI） | 48/48/48/67 | 0/0/0/0 |
| 只列工具名稱 | 驗證：商業簡報 | 46/33/53/32 | 13/0/0/0（僅 A-1 提及） |
| A 證據是否被當成 B/C/D | 驗證：英文自學 | 55/43/47/46 | 50/0/0/0 |
| 長課綱尾段證據 | 校準：行銷研究第 16–17 週 | 70/50/75/72（D 並無證據） | 0/33/67/0 |

**驗證集暴露的問題（沒有依驗證集回頭修改規則）：**

- **具體課綱被低估**：機械設計課 A-1、C-1 只判到 L2（暫定 L4），B-2 漏判。原因是「交一頁比較說明」「以有限元素分析驗算」這類寫法不在產出／檢核線索中，評量段的「比較說明 15%」也沒被連回 A-1。因此這門課的向度分數只有 17–33，雖然仍高於空泛課綱，但明顯偏低。
- 向度分數是「該向度所有細項」的平均，只涵蓋部分細項的課程分數本來就會低。這個分數代表「證據涵蓋程度」，不代表課程品質。
- 教師示範被當成學生練習（A-2、B-2 判為 L2）。
- 英文課綱（B-2、D-2）完全漏判。
- Laya 機率在驗證集的區辨力同樣不穩定（AUROC 0.40–0.95，且每個細項只有 0–4 個正例），與校準集結論一致：不適合用來給分。

## 仍未解決的限制

- **尺規以規則比對中文字詞**。驗證集已看到：英文課綱幾乎無法辨識；「記錄 AI 算錯的地方」「記錄 AI 推估與實際分析的差距」這類寫法沒被 B-2 抓到；「第 8 週：教師示範…」因為有週次，被當成學生練習；具體課綱若用線索以外的寫法描述產出與驗證（例如「交一頁比較說明」「以軟體驗算」），等級會被低估。這些都是規則的已知漏洞，不是隨機誤差。修正它們需要新的驗證案例，才能再次檢驗。
- 規則判斷「有沒有寫」，不判斷活動品質是否足以培養該能力，也無法確認課程實際執行情形。
- 標籤都是暫定的，還沒有教師或專家標註，所以一致率只代表「與 Claude 擬定標籤的一致程度」，不是效度證據。正式使用前，至少需要 2 位以上教師獨立標註，並計算評分者間一致性。
- Laya 零樣本無法分辨細項，機率目前只能作為對照。若要讓模型真正參與判斷，可以考慮以下方案（皆需另行決定，本專案沒有購買服務，也沒有上傳任何課綱）：
  1. 用教師標註的課綱段落微調 Laya（仍在本機，不上傳資料）。
  2. 改用可由使用者自行設定金鑰的外部 LLM API，並事先告知課綱會被送出。
- tokenizer 在罕見字與 emoji 上用 `<unk>` 取代 byte fallback，影響很小，但與官方實作不完全相同。

## 本機執行與測試

- 頁面：在此資料夾執行 `python -m http.server 8765`，開啟 http://localhost:8765/。純靜態網站，無建置步驟。字型與 ONNX runtime 由外部 CDN 載入。
- 功能測試：`npm install`（只安裝校準用的 onnxruntime-node）後執行 `npm test`。測試項目包含：分段不遺失、11 細項定義完整、規則不含範例文字、等級階梯、目標句與否定句、無 AI 課程、只列工具、跨段合併、重排與重複不變、刪除關鍵活動會降級、長課綱尾段、模型機率不改變分數。
- 評分效度（與暫定標籤比較）：`npm run calibrate`，或 `node calibration/run.mjs validation`。首次執行會把 `model/encoder.onnx.part*` 合併到 `.cache/`（不提交）。

功能測試證明程式照設計運作；校準與驗證結果只說明規則和暫定標籤的一致程度，兩者不同。
